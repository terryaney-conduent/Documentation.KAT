OE Schedule

See which clients are in Open Enrollment now, who starts next, and where the busiest days fall.

Turning It On

OE Schedule is off by default. In Settings > Connections, turn on Show OE Schedule Information and save. OE Schedule becomes the first item under Sentinel, with a Dashboard tile and informational What's Happening rows.

The saved default endpoint and Poll (hours) value of 8 are already filled in. The endpoint is a Sentinel base address, not an individual API route. Reads use your existing KAT Management sign-in and require Sentinel Access. The schedule covers all clients from that endpoint; it does not depend on the selected site.

Turning the switch off removes the navigation item, tile and activity rows, stops reads, and discards the cached schedule. If the page was open, you return to the Dashboard. Leaving the endpoint blank while the switch is on instead keeps the navigation item and a link to Connections, but hides the tile and stops polling.

Reading the Schedule

Active means the client's start date is on or before today and its end date is on or after today. Both dates are included. Inactive includes future and ended windows; a pre-period does not make a client active. Today is your computer's local calendar date.

Clients Live Per Day shows the full schedule, with solid peak bars, shaded weekends and a red Today line. Hover a day to see its live clients below the date labels; move into the tooltip to scroll a long list. Separate peak periods are listed separately. Below it, OE Live Windows places each client's window on the calendar. Both charts label Today above the red line. Hover a row for its dates and optional periods.

  • Name matches either the displayed name or client code.
  • Show and the Active/Inactive chips share the same selection. Turning both statuses off leaves no matching rows.
  • Pre-period draws the days before the start date. Correction Period draws the day after the end through the correction date. These choices hide segments and legend entries, not clients.
  • Sort starts at Start ascending. Choose Name, Start or End; choosing the current field again reverses its direction.

Filters and sorting change only the Gantt rows. Header counts, the daily chart, median and overall window always describe the full schedule. For an even number of windows, the median is the upper middle length. These choices last for the window and are not saved to Settings.

Dashboard and What's Happening

The OE Schedule tile shows Clients, Peak Live, Live Today and Upcoming, followed by a daily sparkline. Its red underline marks today. The season year is the earliest start year plus one.

In OE Now lists the earliest ending windows first, showing five initially. Days Left includes today; the final day reads Last day. Upcoming includes everyone starting within seven days; when fewer than five qualify, it fills with the next starts up to five. Three rows show initially. Each list has its own Show N More and Show Fewer; Upcoming expands only its eligible pool, while its callout counts all future windows.

Click a tile or client row to open the page. Settings > Display > Dashboard can reorder or hide this tile without stopping polling.

What's Happening uses the same Active clients and Upcoming pool. Each group folds into one row when it has more than five clients; hover for their details. These rows are informational, have no dismiss or write action, and never increase rail badges or N need you. Rows disappear while a read is loading or has failed.

Refreshing and Failures

The schedule loads at startup when enabled, when you enable it or set an endpoint, and every Poll (hours) interval regardless of which page is visible. The accepted range is 1–168 hours. Refresh on the page or tile reads immediately; F5 does so while the page is open. Concurrent reads are not duplicated.

Cached counts update after local midnight or resume without waiting for another read. As of remains the time of the last successful response.

An empty schedule says Sentinel has no Open Enrollment windows configured. Missing sign-in or denied access explains the access requirement; unreachable Sentinel explains the connection failure. If a prior successful schedule exists, it stays visible below the failure message until a read succeeds. No OE action writes to Sentinel.
