Cleaning up your Work Item lists

Task comments now support @mentions. Type @ in the Comment field to open the people picker, then search for and select the teammate you want to mention. See what you can do in task comments.

Back in Work Item Query results, here's what changed:

  1. A consistent action bar. Return Triaged, View Query in TFS, Refresh, and Help stay visible as icon buttons instead of moving into an overflow menu when the window narrows.
  2. Create Work Item stays beside the filter. The + button is always just to the left of the filter box.
  3. One box for filtering and task lookup. Type @follow to show only items you follow in the current query. To look up a task by ID, even if it's outside the current query, type #1234567 and press Enter. This replaces the separate Task ID Lookup control.
  4. Follow or unfollow a task. Use Follow or Unfollow in the row menu. The magnifying-glass icon in the State chip marks a task you follow.
  5. Share KCC links in Microsoft Teams. Use Share KCC Link from the row menu, or press s on the active row. Make this your go-to for sharing work items with KAT teammates in Teams: the link opens the task in KAT Command Center. It's also available in the new-task confirmation when Confirm new work item creation is enabled in Settings > Work Items.

Streamlining Pipeline builds and commits

The Pipeline commit comparison is easier to focus on, with a simpler page action bar and build controls beside the commits they affect.

  1. Choose your comparison, then refresh. The page-wide action bar now focuses on the From and To pickers, alongside Refresh and Help. Changing either picker no longer immediately calls TFS to rebuild the comparison. Instead, the affected From/To callout card gets a striped, stale appearance. Set both ends, then click the Refresh Pipeline icon to rebuild the commit differences.
  2. Find your commits quickly. Use Filter commits... to search by Git hash, creator, or comment. When reviewing whether a release is ready for a particular environment, filter to your commits to quickly inspect what the comparison includes. Repositories with no matches disappear; with Show Pending on, empty release and Needs Build groups disappear too.
  3. Build controls live beside the commits. Show Pending and Queue Build now sit on the right of the Commits bar. As before, Show Pending appears only when there is pending work: commits awaiting a TFS build, unreleased commits, or newer release candidates. Queue Build is enabled when there are Needs Build commits or the latest build attempt failed, regardless of the filter or whether pending commits are shown.
