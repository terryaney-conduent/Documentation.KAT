Open Enrollment at a Glance

OE Schedule brings the enrollment calendar into the first Sentinel navigation item. See the busiest days in Clients Live Per Day, then follow each client's window in OE Live Windows, including optional pre-period and correction segments. Filter or sort the client rows without losing the full-season picture above them.

The Dashboard tile shows who's live, who starts next and peak dates. What's Happening groups the same Active and Upcoming clients without adding to your action counts.

It is off by default. Turn on Show OE Schedule Information in Settings > Connections when enrollment season arrives. The endpoint is already filled in and polling defaults to eight hours, with manual refresh whenever needed. Turning it off removes the navigation item, tile and activity rows and stops polling.

  • A new CPU Load chart follows Response Time, plotting each node's average CPU for the selected Requests period. It requires updated Balancer and Sentinel versions.
  • Response Time, CPU Load and Request Rate charts all follow the selected Requests period, capped at 12 hours, and plot the point still being collected instead of waiting for it to finish.
  • Request Rate shows successful requests per hour, with Show Total and Show Extremes switches.
  • Charts always fit on one row. When three don't fit, a sticky Charts bar shows icon and arrow controls to move between them, two or one at a time.
  • Charts with no activity in the period now say so, rather than suggesting Balancer and Sentinel need updating.
  • Each node shows a request beam scaled to the busiest node, so load differences are visible at a glance: always in card views, and in the table and Dashboard tile when there is room.
  • Table CPU and memory meters line up after the longest node name, as they do on the Dashboard tile, and capacity always follows the node name.
  • Colored 60s Avg values are bold everywhere they appear; very slow averages in the table show as 9,999!ms with the exact value in the tooltip.
  • The status counts in the header are now filter chips, like CalcEngines. Select one or more statuses to show only those sites; counts always describe the full list.
  • Warning and danger colors are easier to tell apart, particularly in light mode, in the history column and status chips.
  • Alerts show separate badges for warnings, slowness alerts and failures in each hour. Quiet hours stay dim, counts above 99 show as 99!, and the tooltip lists the exact counts.
  • Settings > Repository Status > What's Happening Display Counts lets you independently include repositories that are behind, ahead or dirty in the Dashboard list and counts. All three start on; turning one off leaves Repository Status rail counts, conflict notices and root warnings visible.
  • Ahead and dirty repositories now appear as red needs-action alerts; behind repositories remain amber. Each category counts a repository once across its checkouts and groups separately at five or more. A repository needing Sync counts once in both behind and ahead.
  • Settings › Work Items › What's Happening Display Counts chooses whether severity, priority and old thresholds add Work Items to What's Happening. Severity starts on, priority and old start off; rail badges still count every threshold.
  • Dashboard rail badges now match What's Happening's action and attention counts.
  • Creating a Hangfire job no longer replaces a job with the same ID created elsewhere during the upload; the rejection appears under Suffix.
  • Work Items reliably sorts newest changes first when no column sort is selected, with missing or invalid dates last.
  • Warning rows in Repository Status and other tables retain their intended tint instead of turning pink in newer WebView versions.
