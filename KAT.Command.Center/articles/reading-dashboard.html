Orientation · 6 minute read

Read the dashboard without guessing.

The rail tells you where something needs you. The tiles give each area's headline. What's Happening lists what needs you, and what is moving, right now. Select a section in the rail for its evidence and controls.

Command Center at a glance

Select a numbered area to learn how it helps you read the dashboard and make informed decisions. This is the default layout; Settings > Display > Dashboard reorders or hides any tile and can add a Work Items query as a KPI.

Work Items query KPI

A Work Items query turned on in Settings > Display > Dashboard gets a KPI tile listing its tasks in the query's saved Default Sort, initially Changed (newest first). Manual sorting on the Work Items page does not change the tile's order. Each row shows ID, Changed date and Title, led by the work item type's icon, with a long title cut short (hover it for the whole title). Above the list, the total number of tasks is followed by the query's threshold counts (Critical, High Severity, Top Priority, High Priority and Old), each number colored the way its chip is on the Work Items page; a count of zero is left out. Click a row to select that query on the Work Items page and open the task; click elsewhere on the tile to just open the query.

What's Happening

OE Schedule is off by default. Turn on Show OE Schedule Information in Settings > Connections to add its tile and the first Sentinel navigation item. The tile shows Clients, Peak Live, Live Today and all Upcoming windows, a daily sparkline, and independent expandable In OE Now and Upcoming lists. Five live and three upcoming clients show initially; Upcoming expands within the next-week/next-five pool, not all future windows. A red sparkline underline marks today. Click the tile or a client to open the schedule.

The list and section rail badges use the same facts, but do not always count the same things. The Pipeline badge includes approvals, which appear as chips on a release rather than separate rows. A query excluded from What's Happening still badges. The global What's Happening Display Counts switches also affect this list only: Severity starts on; Priority and Old start off, without changing Work Items or query badges.

Repository Status has its own What's Happening Display Counts switches for behind, ahead and dirty repositories, all on by default. Enabled reasons combine into one row per repository at its strongest color: behind and conflicts are amber; ahead and dirty are red. Five or more repositories of the same color fold into one row, which counts once here. Every Repository Status row can be dismissed; its current reasons stay hidden until restart, including after polls and rescans, but a different reason can appear on the same repository. Repository Status rail badges still count each repository once at its strongest color, independent of these switches and dismissals; root warnings count separately.

The Dashboard rail entry is different: its red and amber counts match this list's need action and need attention counts exactly. They count displayed rows, including one for a folded group, not underlying items or the sum of other rail badges. Dismissing an actionable row updates both counts together.

Some rows describe a state: they stay while it is true and go when it is not. Others are news: they have a × and end on their own.

Approval chips show one chip per stage of a release you can approve now, all on that release's newest row: the stage that most recently started or finished deploying. As stages start and finish, the chips move to the newest row, and an older finished row then removes itself. Clicking a chip asks you to confirm, then approves.

Rows about another site select that site when clicked, then open the section. An approval chip approves without changing site; the confirm names the site. More than five rows of one kind fold into a single row that opens their section, and its tooltip lists the first ten. Rows for builds and releases the app is watching are never folded.

Colour in the list

  • The left edge is the row's tone:
    • red something is broken: a failed stage or build, a failing site, an unavailable section, or critical or priority 1 items over their threshold.
    • amber something waits on you: a checkout, or high severity, priority 2 or old items. A checkout of yours turns red once it is older than My checkouts turn red after (Settings > Releases); a team member's stays amber.
    • blue it is in flight.
    • green it has just deployed.
    • No edge means it is for your information only.
  • Warning and danger rows also use bold, tone-coloured main text. Elapsed times stay muted and embedded chips keep their own colours.
  • The icon is the rail icon of the section the row belongs to, in that section's colour.
  • Environment chips are coloured exactly as they are on the Pipeline page: the environment's own colour once deployed, while deploying (with a spinner) or waiting for approval, red when failed, and grey while queued.
  • Red text on a row means an action you took was refused. Hover the row to read TFS's message.

Rail badges

A badge counts what in its section needs you. Dashboard, Work Items, CalcEngines and RBLe Balancer can split their counts into red and amber badges. A rail group's badges (shown while the group is closed) add up its entries' red and amber counts separately.

Diagnostics

Diagnostics, under Tools in the rail, opens a menu beside the rail rather than a page. The app writes what it does - each refresh, every TFS call and how long it took, and any failure - to a daily log file in %LOCALAPPDATA%\KAT.Command.Center\logs, and keeps the last 14 days.

Menu item What it does
Open today's log Opens today's log file in your editor. Before anything has been logged today, it opens the log folder instead.
Snapshot current UI Saves the screen exactly as it is, as an HTML file in the log folder, and names the file in a message at the bottom of the window. Snapshots older than 14 days are deleted.
Open log folder Opens the log folder in File Explorer.

Reporting a problem? Take a Snapshot current UI while the problem is on screen, then use Open log folder and attach the snapshot and today's log (kcc-yyyyMMdd.json) when you contact the KAT team.

Sites with a release in flight

The site picker answers one question about every site at once, without you having to select them one at a time: has its newest release finished publishing to every environment? If it has not, the site carries an amber dot - on its row in the dropdown, and on the closed picker when it is the site you are looking at.

Typing * filters the list to sites carrying a dot. Anything you type after it still has to match as usual, so *sample means outstanding and matches "sample" - not either one on its own. The * only does this at the front of what you type; it is a mode switch, not a wildcard.

The dots are filled in by a background sweep that runs shortly after the app starts and continues to periodically poll in the background. It never blocks anything you are doing: sites light up as their answers arrive, and refreshing a site updates its own dot immediately from data that refresh already fetched. A site the sweep cannot reach keeps whatever dot it had rather than going dark, because a failed call is not evidence that a release finished.
